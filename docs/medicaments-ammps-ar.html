الفكرة العامة والبنية

المشكلة: عندما يكتب الطبيب وصفة (ordonnance)، كان يكتب اسم الدواء يدوياً بالكامل. الهدف: اقتراح الأدوية من القائمة الرسمية المغربية التي تنشرها الوكالة المغربية للأدوية والمنتجات الصحية AMMPS (حوالي 9,950 دواء).

القرار المعماري الأهم: ثلاثة أنواع من قواعد البيانات

Cabinova يعمل بنظام قاعدة بيانات لكل عيادة (database-per-tenant). لكن قائمة الأدوية واحدة للجميع، فلا معنى لنسخها 100 مرة. لذلك أضفنا قاعدة بيانات مشتركة جديدة:

قاعدة المنصة (Platform DB)

العيادات، الاشتراكات، مستخدمو Super Admin، سجل التدقيق.
كانت موجودة من قبل. في clinic-api اسمها CATALOG.

قاعدة الأدوية (جديدة)

قائمة AMMPS الوطنية + سجل عمليات الاستيراد.
واحدة للجميع. admin-api فقط يكتب فيها. العيادات تقرأ فقط.

قاعدة كل عيادة (Tenant DB)

المرضى، الوصفات… والآن: تخصيصات كل طبيب وأدويته الخاصة.
الربط مع قائمة الأدوية عبر رقم ammps_id فقط.
لماذا لا نربطها بمفتاح أجنبي (foreign key)؟ لأنها قواعد بيانات منفصلة فعلياً، وPostgres لا يستطيع ربط جداول بين قاعدتين. لذلك الربط يتم في الكود (service layer): نقرأ من القاعدتين ثم ندمج النتائج في JavaScript بواسطة الرقم ammps_id.

لماذا اسمها «قاعدة الأدوية» وليس «catalog»؟

الطلب الأصلي سماها catalog، لكن الكلمة مستعملة أصلاً في clinic-api للإشارة إلى قاعدة المنصة (CatalogService). لو استعملنا نفس الاسم لحدث خلط خطير. فاخترنا MEDICINES_DATABASE_URL و@cabinova/medicines-db.

القواعد الذهبية الأربع

  1. الأطباء لا يكتبون أبداً في قاعدة الأدوية المشتركة.
  2. الاستيراد لا يكتب أبداً في قواعد العيادات.
  3. لا يُحذف أي دواء أبداً: الدواء الذي يختفي من الملف يصبح «غير نشط» فقط، لأن وصفات قديمة قد تشير إليه.
  4. سطر الوصفة المطبوع صورة ثابتة (snapshot): لا يتغير أبداً حتى لو تغيرت القائمة لاحقاً.

سجل لكل عملية استيراد: اسم الملف، من قام بها، الحالة (running / success / failed)، وعدد الأدوية المضافة والمعدّلة والمعطّلة، وسبب الفشل إن وُجد.

البحث السريع: امتداد pg_trgm

أضفنا فهارس (indexes) من نوع trigram على الاسم والمادة الفعالة. هذا ما يجعل البحث بجزء من الكلمة سريعاً جداً: كتابة «lipr» تجد DOLIPRANE.

CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX "medications_name_trgm_idx"
  ON "medications" USING gin ("name" gin_trgm_ops);

قراءة ملف Excel الخاص بـ AMMPS

ملف apps/admin-api/src/medicines/ammps-file.ts — دالة «نقية» (pure function): تأخذ bytes الملف وتعيد أسطراً نظيفة، بدون أي قاعدة بيانات. هذا يجعل اختبارها سهلاً جداً.

كيف يُقرأ ملف xlsx؟

ملف .xlsx هو في الحقيقة ملف ZIP يحتوي على ملفات XML. استعملنا مكتبة صغيرة اسمها fflate لفك الضغط، ثم قرأنا الـ XML بأنفسنا:

  1. xl/workbook.xml ← نعرف أول ورقة (sheet).
  2. xl/worksheets/sheet1.xml ← الخلايا سطراً سطراً.
  3. النصوص قد تكون داخل الخلية نفسها (inlineStr، مثل ملفك) أو في قائمة مشتركة sharedStrings.xml (عندما يُحفظ من Excel). ندعم الحالتين.

قواعد التنظيف

  • الأعمدة تُعرف من عناوينها وليس من ترتيبها، مع تجاهل الحروف الكبيرة والتشكيل و«(DH)». الأعمدة الإلزامية: ID AMMPS، Nom commercial، Substance active.
  • الأسعار: دالة parsePrice تفهم كل الأشكال: 
    "4.303.00 DH"  → "4303.00"
"10,70 DH"     → "10.70"
"1.200,50 DH"  → "1200.50"
"SANS PPV DH"  → null
  • الحالة: دالة availabilityOf تحوّل 10 حالات مختلفة إلى 3 فئات (مثلاً «Retiré» و«Suspendu» ← withdrawn).
  • الأسطر السيئة لا توقف كل شيء: سطر بدون رقم صالح يُتخطى مع رقم السطر والسبب. والرقم المكرر نحتفظ بأول ظهور له.
حماية من «القنابل»نرفض الملفات فوق 20 ميغا، ونرفض أي ملف يصبح ضخماً جداً بعد فك الضغط (zip bomb).
النتيجة على ملفك الحقيقي9,947 دواء في 0.2 ثانية، صفر أسطر مرفوضة: 5,217 مسوّق، 3,861 غير مسوّق، 869 مسحوب. 27 اختبار وحدة (unit test).
الخطوة 3

الاستيراد: «الكل أو لا شيء» مع قاعدة الأمان

ملف apps/admin-api/src/medicines/ammps-import.ts.

طريقة العمل (داخل transaction واحدة)

  1. ننشئ جدولاً مؤقتاً ammps_rows وننسخ فيه الملف على دفعات من 1000 سطر.
  2. إضافة: كل دواء غير موجود ← INSERT.
  3. تحديث: فقط ما تغيّر فعلاً (نستعمل IS DISTINCT FROM)، حتى يبقى «آخر تعديل» ذا معنى.
  4. تعطيل: كل دواء نشط غير موجود في الملف ← is_active = false. لا حذف أبداً.
  5. دواء معطّل يعود في ملف لاحق ← يُعاد تفعيله.
لماذا transaction؟لو حدث خطأ في منتصف العملية، Postgres يلغي كل شيء تلقائياً (rollback). القائمة إما تُحدَّث كاملة أو تبقى كما كانت. لا توجد حالة «نصف مستوردة».

قاعدة الأمان (أهم جزء)

قبل أي تغيير، نرفض الملف إذا:

  • يحتوي أقل من 80% من الأدوية النشطة حالياً (ملف مقطوع؟ موقع AMMPS معطّل؟).
  • أكثر من 5% من أسطره غير مقروءة (تغيّر شكل الملف؟).

بدون هذه القاعدة، ملف ناقص قد يعطّل آلاف الأدوية عند كل العيادات في ثانية واحدة.

استيراد واحد فقط في نفس الوقت

استعملنا «فهرس فريد جزئي» (partial unique index): قاعدة البيانات نفسها ترفض وجود سطرين بحالة running:

CREATE UNIQUE INDEX medication_imports_one_running_idx
  ON medication_imports (status) WHERE status = 'running';

وإذا انقطع استيراد بسبب إعادة تشغيل السيرفر، يُحرَّر تلقائياً بعد 15 دقيقة.

أمر سطر الأوامر

pnpm --filter admin-api medicines:import ~/Downloads/medicaments-ammps.xlsx
على ملفكأول تشغيل: 9,947 مضاف. ثاني تشغيل: 0 تغيير. أقل من ثانيتين. 7 اختبارات e2e تغطي كل الحالات.

جداول كل عيادة: تخصيصات الطبيب

Migration رقم 0041_medication_overrides في packages/tenant-db.

الجدول medication_overrides

«نسخة الطبيب» من دواء AMMPS:

  • custom_name, custom_dosage: اسمه وجرعته الخاصة («Doliprane» بدل «DOLIPRANE»). الحقل الفارغ = كما يقول AMMPS.
  • default_posology, default_duration: الجرعة والمدة المعتادة، تُملأ تلقائياً.
  • is_favorite, is_hidden: مفضّل / مخفي من الاقتراحات.
  • base_name, base_dosage: اسم وجرعة AMMPS لحظة الحفظ. الفكرة الذكية هنا: لو غيّر AMMPS الاسم لاحقاً، نقارن ونعرف أن هناك تحديثاً يجب أن يراه الطبيب.

الجدول custom_medications

أدوية غير موجودة في القائمة (تحضيرات صيدلانية، منتجات مستوردة). نفس الطبيب لا يستطيع إضافة نفس الاسم والجرعة مرتين.

type PrescriptionItem = {

  posology: string | null;
  duration: string | null;
  ammpsId?: number | null;            // جديد: من أين اختير
  customMedicationId?: string | null; // جديد
};

واجهة البحث في clinic-api

الملفات في apps/clinic-api/src/medications/.

اتصال «للقراءة فقط»

في database/medicines.module.ts، كل اتصال جديد ينفّذ:

set default_transaction_read_only = on

حتى لو أُعطي clinic-api رابطاً بصلاحيات كتابة بالخطأ، لن يستطيع تعديل القائمة. (اختبار يتأكد من ذلك.)

منطق الدمج — merge.ts (دوال نقية)

  • تجميع العلب: AMMPS يكتب كل حجم علبة كسطر منفصل (Amlor 10 mg ×3 مرات). نجمعها بحسب (الاسم، الجرعة، الشكل) ونختار العلبة المسوّقة الأرخص كممثل.
  • تطبيق التخصيص: اسم الطبيب يغلب، والمخفي يُحذف.
  • لا نقترح أبداً المسحوب أو غير النشط.
  • الترتيب: المفضلة أولاً ← الاسم يبدأ بما كُتب ← كلمة في الاسم ← المادة الفعالة ← المسوّق قبل غير المسوّق ← أبجدياً.
  • «محدّث من AMMPS»: فقط إذا غيّر AMMPS شيئاً كان الطبيب قد أعاد تسميته.

الإكمال التلقائي داخل الوصفة

medication-input.tsx (الحقل) وprescription-editor.tsx (المحرر) في clinic-web.

ما يراه الطبيب عند الكتابة

  1. ⭐ المفضلة أولاً مع الجرعة المعتادة بخط مائل.
  2. أدوية AMMPS: الاسم والجرعة، الشكل، المادة، عدد العلب، أقل سعر.
  3. أدويته الخاصة (علامة «Perso»).
  4. «Déjà prescrits»: ما كتبه سابقاً.
  5. «Ajouter « … » à mes médicaments» لأي نص مكتوب.

التنقل بـ ↑ ↓ Enter Esc. بعد الاختيار: يمتلئ السطر، تُضاف الجرعة المعتادة، وينتقل المؤشر لحقل الجرعة.

تقنيات مهمة

  • Debounce 200ms: لا نرسل طلباً مع كل حرف، بل عندما يتوقف الطبيب عن الكتابة.
  • React Query: يخزّن النتائج مؤقتاً (staleTime 60 ثانية)، وkeepPreviousData يُبقي القائمة القديمة ظاهرة أثناء التحميل فلا «ترمش».
  • زرّان على السطر المختار: ⭐ مفضّل، و🔖 «احفظ هذه الجرعة كمعتادة».
  • التجديد: قبل نسخ وصفة قديمة نستدعي check-renewal، والأسطر المسحوبة تظهر بعلامة برتقالية.
  • تعديل النص يدوياً يقطع الربط: السطر يصبح نصاً حراً.

صفحة «Mes médicaments» في الإعدادات

apps/clinic-web/src/app/(clinic)/settings/medications/ — للأطباء فقط (السكرتيرة لا ترى القسم).

  • تحديثات AMMPS للمراجعة: «اسمك / القديم مشطوب ← الجديد» مع زرين: «Prendre la nouvelle valeur» أو «Garder la mienne».
  • أدوية AMMPS المخصصة: النجمة، التعديل، والعودة لقيم AMMPS (تحتاج نقرة ثانية للتأكيد قبل المسح).
  • «Personnaliser un médicament»: بحث في القائمة ثم نموذج (الاسم، الجرعة، الجرعة المعتادة، المدة، مفضّل، مخفي).
  • الأدوية خارج القائمة: إضافة، تعديل، مفضّل، حذف.

درس العربية: عزل النص اللاتيني (bidi)

في الواجهة العربية (من اليمين لليسار) ظهر «Crème magistrale urée 10 %» هكذا: «% 10 Crème…». السبب: خوارزمية الاتجاه الثنائي (Unicode Bidi) تعيد ترتيب الرموز المحايدة مثل % والأرقام. الحل: نضع الأسماء داخل عنصر <bdi> الذي يعزل اتجاه النص:

<bdi>{nameOf(c.name, c.dosage)}</bdi>

  1. الحقل ينتظر 200ms بعد آخر حرف (debounce)، ثم يرسل GET /api/medications/search?q=doliprane 1g.
  2. Next.js يمرّر الطلب لـ clinic-api، الذي يعرف العيادة من النطاق الفرعي (subdomain) ويفتح قاعدتها.
  3. يتحقق أن المستخدم طبيب (assertMedical).
  4. يقسّم النص إلى كلمات: ["doliprane", "1g"]. كل كلمة يجب أن توجد في الاسم أو المادة أو الشكل أو الجرعة (والجرعة تُقارن بدون مسافات حتى تطابق «1g» القيمة «1 G»).
  5. من قاعدة العيادة: أدوية الطبيب الخاصة + تخصيصات بأسمائه.
  6. من قاعدة الأدوية (قراءة فقط): الأدوية المطابقة النشطة غير المسحوبة، ثم كل علبها.
  7. من قاعدة العيادة مرة أخرى: تخصيصات الطبيب لهذه الأدوية.
  8. mergeCatalog يجمع العلب ويطبّق التخصيصات، ثم rankSuggestions يرتّب ويأخذ 20.
  9. الواجهة تعرض القائمة. عند الاختيار يُحفظ السطر مع ammpsId تلقائياً بعد 800ms.

مفاهيم يجب أن تفهمها

Database per tenant

كل عيادة لها قاعدة بيانات منفصلة. عزل تام للبيانات الطبية.

Snapshot

نحفظ النص كما طُبع. التغييرات اللاحقة لا تمس الماضي — مهم قانونياً للوصفات.

Override

طبقة فوق البيانات الرسمية: الحقل الفارغ = القيمة الرسمية.

Soft delete (is_active)

لا نحذف، نعطّل فقط، حتى لا تنكسر المراجع القديمة.

Transaction

مجموعة عمليات تنجح كلها أو تُلغى كلها.

Staging table

جدول مؤقت ننسخ فيه الملف ثم نقارن بعمليات SQL جماعية سريعة.

Partial unique index

قيد فريد على جزء من الأسطر فقط (هنا: الحالة running).

pg_trgm

يقسّم النص لمقاطع من 3 أحرف لتسريع البحث بجزء من الكلمة.

Pure function

دالة بدون آثار جانبية: نفس المدخل = نفس المخرج. سهلة الاختبار.

Read-only session

طبقة حماية ثانية فوق صلاحيات الدور.

Debounce

انتظار توقف الكتابة قبل إرسال الطلب.

Bidi isolation

<bdi> يمنع خلط اتجاه النص اللاتيني داخل صفحة عربية.

قائمة التشغيل في الإنتاج

  • إنشاء قاعدة Neon جديدة للأدوية، ووضع رابط المالك في apps/admin-api/.env كـ MEDICINES_DATABASE_URL.
  • إنشاء دور للقراءة فقط (SQL في README)، ووضع رابطه في apps/clinic-api/.env.
  • تشغيل pnpm --filter admin-api db:seed للصلاحيات الجديدة.
  • ملء القائمة: pnpm --filter admin-api medicines:import <ملف.xlsx>.
  • تطبيق migration 0041 على العيادات بزر Migrer (مع 0030–0040 المعلّقة).
  • لاحقاً، كل شهر: رفع الملف الجديد من Super Admin › Médicaments.
